VERDICT
The principal CPU correctness fixes landed. Multi-token cache appends are now causal,
the causal sliding window retains the correct cross-block history, CPU import works
without Triton, and the cache no longer concatenates unused raw K/V. Independent
checks confirm those improvements. This is not a clean production sweep yet: cache
priming now has an unbounded N*R*d temporary, long-position FP16 normalization fails,
hybrid cache support is still absent, and GPU training/dtype paths need attention.
Large-context benchmark rows are now explicitly projections, which is an improvement;
that does not validate their arithmetic, memory model, or the remaining measured rows.

NUMBERED REMAINING WORK - PASTE-READY
Address these in priority order. Keep the tested algebra intact. Each item names
its evidence level and the regression gate needed before closing it.

HIGH
1. Bound cache-append workspace by chunk_size, not full append length.
   Location: tensorsat/attention.py:113-116; benchmark_rigorous.py:161-162.
   Evidence: STATIC NEW REGRESSION in the causal-cache fix. All N new tokens form
   token_kv_chunk and causal_intra of shape (B,H,N,R,d); chunk_size is ignored in
   this branch. The ordinary non-cache forward does process internal chunks.
   At B=1,H=8,N=1,000,000,R=16,d=64,FP32, EACH such tensor is
   1*8*1,000,000*16*64*4 = 32,768,000,000 bytes. This is a tensor-size calculation,
   not a measured peak, and excludes Q/K/V and other allocations. No large run
   was attempted. The new benchmark primes up to 16,384 tokens through this path.
   Required: process cached appends in bounded internal chunks, maintaining causal
   per-position output and final state. Test an append larger than chunk_size,
   compare with stepwise/full prefill, perturb a future token, and profile workspace.

2. Preserve training gradients on the Triton path, or explicitly restrict it to inference.
   Location: tensorsat/triton_kernel.py:92-111; attention.py:81-84;
   hybrid.py:82-85; model_wrapper.py:26-31.
   Evidence: STATIC. The wrapper allocates an output with torch.empty and fills it
   using a raw Triton launch. There is no registered backward/custom autograd path
   in the repository connecting that output to Q or U. Default use_triton=True on
   CUDA therefore cuts the Q/K feature projection gradient paths. CPU fallback
   gradients work, so the CPU test suite cannot catch this.
   Required: CUDA backward comparison against the PyTorch projection for inputs,
   bases and q_proj/k_proj weights. Until then use a differentiable fallback when
   gradients are required, or reject unsupported training explicitly. Do not infer
   trainability from finite forward outputs or the unrelated adapter-loss test.

3. Define and enforce GPU projection dtype semantics end to end.
   Location: tensorsat/triton_kernel.py:92; attention.py:135-136,173-174;
   hybrid.py:181-186; test_tensorsat.py:123-125.
   Evidence: STATIC GPU RISK. The Triton wrapper always returns FP32 while the
   einsum fallback preserves the input dtype. Casting a module to FP16/BF16 leaves
   its output Linear weights low precision while the Triton/global path carries
   FP32 output. Outside autocast this leads to incompatible Linear operand dtypes;
   merely casting the kernel result is not a complete accumulation policy.
   Existing dtype tests explicitly disable Triton. No CUDA failure is claimed as
   reproduced here.
   Required: CUDA FP32/FP16/BF16 tests with and without autocast, dtype assertions,
   reference tolerances and backward checks. Specify accumulator and output dtype.

4. Keep long-sequence positions and normalization out of FP16 storage.
   Location: tensorsat/attention.py:126,164; tensorsat/hybrid.py:174.
   Evidence: REPRODUCED CPU. arange uses x.dtype. FP16 cannot represent position
   70,001; the scale becomes Inf and a finite attention contribution is divided
   to zero. A synthetic cache with seq_len=70,000 and a small constant finite
   summary needs only one token to reproduce it. Matched FP32/FP16 models produce
   a non-bias contribution of about 6.55e-5 versus exactly zero in the FP16 case.
   This is a normalization failure, not a 70,000-token memory benchmark.
   Required: FP32-or-better position/normalization math with an explicit cast policy.
   Test both cache and prefill paths around long positions without allocating huge
   test sequences; test BF16 position rounding as well.

5. Implement hybrid cache semantics or reject unsupported cache requests clearly.
   Location: tensorsat/hybrid.py:131-186.
   Evidence: REPRODUCED CPU plus source. use_cache/kv_cache are accepted but never
   consulted; use_cache=True returns cache=None. Repeated one-token calls lose
   historical local and global context.
   Required: a defined local K/V ring buffer, global state/decay semantics and
   position tracking, then chunked/stepwise/full comparison tests. If incremental
   support is out of scope now, raise a clear error rather than silently ignoring it.

6. Separate hybrid numerical semantics from its computational chunk_size.
   Location: tensorsat/hybrid.py:156-179; tensorsat/stabilizer.py:69-72.
   Evidence: REPRODUCED CPU. Same weights/input, only chunk_size changed from 8 to
   16: max output difference 0.005835 on B=1,N=41,D=32,H=2,R=3,W=8 after the
   independent tests described above. Prior history is normalized at block starts;
   intra-block history is not. Chunk contributions also receive no internal
   per-token decay weighting. Thus gamma^C*old + sum(new) is not repeated
   per-token gamma*state + new, despite the recurrence-style framing.
   Required: decide and document the intended recurrence, then implement a reference
   and partition-equivalence tests. If chunk_size intentionally changes the model,
   expose it as a semantic model parameter rather than a memory/performance knob.

7. Honor noncausal mode consistently in hybrid attention.
   Location: tensorsat/hybrid.py:100-124,152-179.
   Evidence: REPRODUCED CPU plus source. Global accumulation is always causal,
   regardless of is_causal=False. With the gate selecting the global branch,
   perturbing the last token leaves the first output unchanged. The local branch
   also switches definitions: N<=W uses unrestricted full attention, while N>W
   uses a centered abs(key-query)<=floor(W/2) band. At W=4,N=4 that full-attention
   shortcut differs from its own centered-mask rule by 1.50 in the tested sample;
   N=5 matches that rule within 2.39e-7. Even W gives W+1 interior keys.
   Required: define noncausal window width and global semantics. Test odd/even W,
   N just below/equal/above W, and future sensitivity. Or explicitly disallow mode.

8. Parse DIMACS by zero-terminated clauses, preserving the empty clause.
   Location: tensorsat/cnf_preprocessor.py:14-24.
   Evidence: REPRODUCED CPU. The parser treats lines as clauses and discards zeros.
   An input with header for one variable/one clause and a single 0 yields [],
   dropping the empty unsatisfiable clause. A clause split over two lines becomes
   two clauses; two zero-terminated clauses on one line become one clause.
   Required: stream literal tokens until each 0, retain empty clauses, validate
   declared counts/literal bounds and malformed trailing input. Test all three
   cases and compare satisfiability/model counts on tiny formulas by enumeration.

12. Replace universal absolute-error guarantees with measured numerical contracts.
    Location: README.md:42-43,100-102; test_tensorsat.py:79,94,141,151.
    Evidence: REPRODUCED CPU. With seed 1701, D=64,H=4,R=5,N=37,chunk=7,
    inputs multiplied by 10, FP32 step/prefill max difference is 7.38e-7, not
    universally <1e-8. For FP64 n_bits=3 contraction with numpy seed 0, the

    Required: input scale/dtype/shape domains, atol+rtol and reference precision,
    finite checks, multiple deterministic seeds, explicit separation of exact
    integer coefficients from floating-point contraction error.

13. Demonstrate adapter/model portability and quality instead of equating APIs.

    Evidence: STATIC / VALIDATION GAP. Distillation targets are real causal SDPA,

14. Align scientific solver claims with actual algorithms and resource scaling.
    Location: scientific.py:2-6,28-40,65-95; uncrossing.py:52-68.
    Evidence: STATIC plus the passing periodic residual test. The Poisson routine
    is a conventional 2D periodic FFT solve with the discrete five-point symbol,
    not singlet-decomposed boundary decoupling; no 3D/covariance implementation is
    present. Nonzero-mean RHS has its zero mode silently discarded, so document
    the mean-removal/compatibility convention. The contractor/generator materialize

    Required: accurate scope/docstrings, analytic manufactured-solution and residual

    comparisons against the direct O(dim^2) swap contraction. Preserve the passing

15. Make stabilizer arithmetic safe before promising zero FP16/BF16/FP8 overflow.
    Location: stabilizer.py:5-9,31-38,69-72; hybrid.py:164-179;
    README.md:119-122.
    Evidence: REPRODUCED CPU. StateRMSNorm.half() on finite entries equal to 300
    returns all zeros because state**2 overflows FP16 before normalization. An
    already infinite state produces NaN. No normalization can recover information
    after overflow. The unnormalized intra-chunk product/cumsum remains exposed;

    Required: higher-precision squares/reductions/state accumulation, finite checks
    and an explicit rescaling/cast policy; adversarial amplitude tests, chunked
    long-context tests and supported-dtype GPU tests. Document bounds and withdraw
    universal FP8/billion-token guarantees until validated on a supported path.
